# YouTube Music Bulk Add to Playlist Pro 3.0.4

Скрипт для Tampermonkey: `YouTube Music Bulk Add to Playlist Pro-2.0.user.js`.
Назву файла збережено, версію всередині оновлено до 3.0.4.

## Як запустити

1. Відкрий старий скрипт у редакторі Tampermonkey й заміни **весь** його вміст вмістом оновленого `.user.js`. Збережи. Якщо встановлюєш окремим скриптом, вимкни старий, щоб не запускати обидва.
2. Перезавантаж YouTube Music. Увійди в акаунт / профіль, який може редагувати цільовий плейлист.
3. Відкрий **головну сторінку виконавця** — адресу `https://music.youtube.com/channel/UC…` або `/browse/UC…`, або `/@ім’я` (наприклад `/@KingGnuOfficial`), параметри адреси на кшталт `params` або `si` дозволені. На головній сторінці видно розділи пісень, альбомів і синглів. Скрипт не призначений для головної сторінки сервісу чи звичайного відеоканалу.
4. Натисни **ДОДАТИ ВСЕ В ПЛЕЙЛИСТ → 1. Зібрати пісні**. Прокручувати каталог вручну не потрібно. На цьому етапі плейлист не змінюється.
5. Перевір ім’я виконавця, цільовий плейлист і кількість нових пісень. У панелі видно перші 100; кнопка JSON зберігає повний зібраний список.
6. Натисни **2. Додати N пісень**. Залиш вкладку відкритою до завершення. Потім відкрий / онови цільовий плейлист.

Твій плейлист уже заданий за ID: `PLlsCQDB_ve7YB19JET-pc0TN255DYOId0`. Його назва не впливає на вибір. Поле дозволяє вказати інший звичайний плейлист.

## Що збирається

- Аудіотреки з розділу пісень виконавця та його повного списку пісень, якщо сайт дає посилання на нього.
- Треки з усіх релізів розділів Albums та Singles / EPs, включно з наступними сторінками списків.
- Інші видання альбомів із розділу Other versions, якщо відповідний прапорець увімкнений.

Кліпи, звичайні користувацькі відео, подкасти та явно недоступні треки відсіюються. Рекомендовані виконавці, радіо й сторонні плейлисти не обходяться. Розділ збірок «Appears on» не обходиться: ці альбоми можуть містити багато чужих пісень.

«Усі» тут означає пісні з перелічених розділів каталогу, які YouTube Music повертає для твого акаунта й регіону. Це не гарантія повної дискографії: приховані, вилучені, регіонально недоступні релізи та окремі участі у чужих збірках можуть не потрапити до списку.

## Дублікати, порядок і зупинка

Дублікати визначаються **за ID треку**, а не за назвою. Той самий ID з різних альбомів додається один раз. Різні видання, ремастери й записи з іншими ID залишаються окремими піснями.

Цільовий плейлист читається до кінця, навіть якщо там понад 900 треків. Перед записом він перевіряється повторно. Нові треки надсилаються пакетами по 25 із паузами між запитами. Скрипт не сортує плейлист: надсилає пісні в порядку першого виявлення; розташування нових записів залежить також від налаштувань плейлиста.

Кнопка **Зупинити** припиняє подальші запити. Уже надісланий пакет може завершитися. Якщо сталася помилка або закрилася вкладка, відкрий виконавця й знову натисни **Зібрати пісні**: вже наявні ID буде відсіяно. Автоматично повторювати непідтверджений запис скрипт не буде.

Повідомлення про завершення показується після підтвердження записів сервером і повторного читання цільового плейлиста.

## Якщо виникла помилка

У панелі є **Журнал**. Для діагностики достатньо його тексту, адреси виконавця й назви браузера. Cookies та заголовки авторизації надсилати не потрібно.

- Немає конфігурації: перезавантаж сторінку й переконайся, що Tampermonkey виконує скрипт у контексті сторінки (`@grant none`).
- Немає сесії / HTTP 401 або 403: перевір вхід, вибраний профіль і можливість вручну додати пісню до цього плейлиста.
- HTTP 429: припини запуск і спробуй пізніше.
- Невідомий формат / продовження: сайт міг змінити структуру відповіді; потрібне коригування парсера.

## Технічні деталі й перевірка

Це браузерні запити на тому самому домені `/youtubei/v1/…` з поточною сесією YouTube Music. Власний ключ Google Cloud / YouTube Data API не потрібен. Внутрішній сервіс може змінюватися та застосовувати власні обмеження; необмеженої швидкості це не гарантує. Скрипт не надсилає дані стороннім сервісам і не експортує сесію в JSON.

Формати перегляду каталогу, пагінації та редагування звірено з реалізацією [ytmusicapi](https://github.com/sigma67/ytmusicapi/tree/main/ytmusicapi): [browsing.py](https://github.com/sigma67/ytmusicapi/blob/main/ytmusicapi/mixins/browsing.py), [playlists.py](https://github.com/sigma67/ytmusicapi/blob/main/ytmusicapi/mixins/playlists.py), [continuations.py](https://github.com/sigma67/ytmusicapi/blob/main/ytmusicapi/continuations.py). Бібліотека не є залежністю скрипта.

Локальні перевірки:

```sh
node --check 'YouTube Music Bulk Add to Playlist Pro-2.0.user.js'
node tests/youtube-music-bulk-add.test.cjs
```

Тести використовують змодельовані відповіді: список із 1000 треків, два формати пагінації, фільтрування відео, зупинку, підтвердження записів і сценарій збирання → перегляд → додавання → повторна перевірка. Вони не звертаються до живого акаунта. Реальне додавання через Tampermonkey в авторизованому браузері користувача ще потребує перевірки.

Версія 3.0.1 створює панель без `innerHTML`, примусово задає її видимість і відновлює її після навігації YouTube Music. **Alt+Shift+P** відкриває панель. Якщо Tampermonkey показує запуск, але панелі немає, відкрий консоль Firefox (**Ctrl+Shift+K**), перезавантаж сторінку та перевір повідомлення `[YTM Bulk Add 3.0.4]` і помилки зі згадкою скрипта.

Версія 3.0.2 виправляє перевірку адреси виконавця: параметр `params` більше не блокує запуск, також розпізнається `/browse/MPLAUC…`. Невідомі адреси показуються в повідомленні для діагностики.

Версія 3.0.3 розпізнає адреси `/@ім’я`: отримує UC ID через `navigation/resolve_url`, а потім збирає каталог за цим ID. Формат запиту звірено з [YouTube.js resolveURL](https://github.com/LuanRT/YouTube.js/blob/main/src/Innertube.ts). Локальні тести перевіряють чотири надані UC-адреси й обробку @KingGnuOfficial зі змодельованою відповіддю сервера; живий каталог цих виконавців не перевірено.

Версія 3.0.4 підтримує порожній цільовий плейлист, у початковому `musicPlaylistShelfRenderer` якого відсутнє поле `contents`. Невідомі або пошкоджені продовження списку й надалі зупиняють перевірку. Журнал показує окремо читання цільового плейлиста й каталогу виконавця.
